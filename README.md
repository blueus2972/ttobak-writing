# 또박또박 · 손글씨 연습장과 학급 제출함

문구·격자·서체를 골라 손글씨를 연습하고, 펜으로 쓴 글을 이미지로 저장하거나 교사에게 제출합니다.

## 학생 접속 방식
- 첫 접속: ‘처음 시작해요’ → 이름, 비밀번호, 비밀번호 확인, 학급 코드 → 가입 후 바로 입장.
- 다음 접속: ‘다시 왔어요’ → 처음 정한 이름과 비밀번호만 입력.
- 비밀번호 8~128자. 로그인 이름은 프로젝트 전체에서 유일하며 같은 이름이 있으면 반·번호를 붙입니다.
- 가입한 학생은 해당 학급에 자동 등록됩니다. 학생 이메일은 입력받지 않습니다.
- 비밀번호는 Supabase Auth가 관리합니다. 앱 DB·브라우저에 평문 비밀번호를 저장하지 않습니다. Auth 로그인 세션만 브라우저에 유지하며 로그인 이름을 편의상 기억합니다.

## 화면
- `/` 손글씨 연습장: A4 여러 장, PNG 저장, PDF/인쇄, 펜·지우개, 제출.
- `/teacher.html` 교사: 이메일 로그인, 학급 생성, 자동 등록 학생 관리, 표시 이름·번호 수정, 입장 중지·재개, 제출 검색, 이미지 확인, 피드백.
- `/student.html` 학생: 이름·비밀번호 가입/로그인, 사진 제출, 내 제출물·피드백.
- `/setup.html` 운영자 연결 안내.

## Supabase 설정 순서
1. 새 프로젝트라면 SQL Editor에서 `supabase/schema.sql`을 **한 번** 실행합니다. 이미 적용한 프로젝트라면 다시 실행하지 않습니다.
2. 이어 `supabase/name-password.sql`을 **한 번** 실행합니다. 비밀번호 계정·요청 제한·학생 권한의 추가 마이그레이션입니다. 이전 입장 코드 학생 자료를 삭제하지 않습니다. 새 이름 계정은 새 명단으로 생성됩니다.
3. 교사 이메일을 허용 목록에 등록합니다.
   ```sql
   insert into ttobak_private.teacher_allowlist(email)
   values(lower('teacher@example.com')) on conflict do nothing;
   ```
4. Authentication의 Email/Password와 교사 이메일 인증을 활성화합니다. 신규 학생 가입은 Edge Function이 Auth 관리 API로 처리하므로 학생 이메일 인증은 필요하지 않습니다. Anonymous Sign-Ins도 켜 둡니다. 학생 이름·비밀번호를 확인하기 전에 임시 인증 세션을 만들며, 성공 후 정식 학생 계정 세션으로 바꿉니다. 기존 익명 학생이 있다면 그 계정을 없애지 않습니다.
5. Edge Function `student-account`를 배포합니다.
   ```sh
   supabase functions deploy student-account --project-ref YOUR_PROJECT_ID 
   ```
   또는 Supabase 대시보드 Edge Functions에서 `supabase/functions/student-account/index.ts` 내용으로 같은 이름의 함수를 배포하고 이 함수의 Verify JWT를 켜 둡니다. 프런트엔드가 먼저 임시 인증 세션을 만든 뒤 호출하며, 함수 안에서 이름·비밀번호를 검증하고 DB 기반 요청 횟수를 제한합니다.
6. 함수 Secret `WRITING_ALLOWED_ORIGINS`를 실제 Vercel 사이트 Origin으로 설정합니다. 여러 주소는 쉼표로 구분합니다. 함수의 기본 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase 제공 서버 환경 변수를 사용합니다. 관리자 키를 브라우저·GitHub·Vercel 정적 환경 변수에 넣지 않습니다.
7. 교사 가입 확인 링크를 위해 Site URL/Redirect URLs에 Vercel 주소를 등록합니다.
8. 현재 프로젝트 공개 연결 정보는 `supabase-public.json`에 반영되어 있습니다. 다른 프로젝트를 연결할 때는 Vercel에 공개 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 등록해 덮어쓸 수 있습니다. 기존 공개 anon 키는 `SUPABASE_ANON_KEY`로 사용할 수 있습니다. 최신 커밋으로 재배포합니다.
9. 테스트 학급에서 학생 최초 가입→나가기→다른 기기에서 이름·비밀번호 로그인→제출→교사 피드백→학생 확인을 검증합니다.

URL·공개 키만으로는 스키마와 서버 함수를 배포할 수 없습니다. Supabase 프로젝트 운영자 권한으로 위 설정을 한 번 수행해야 합니다. 연결 전에도 연습장·PNG 저장은 동작합니다.

## 인증과 학생 관리
로그인 이름은 서버에서 NFKC 정규화, 공백 정리, 영문 소문자화 후 비교합니다. 내부 무작위 Auth 이메일은 학생에게 입력받거나 공개 로그인 조회로 노출하지 않습니다. 로그인 이름→Auth 계정 매핑은 비공개 스키마에 보관하고 서버 함수 전용 RPC만 조회할 수 있습니다. 이름이 중복되거나 학급 코드가 잘못되면 기존 계정에 연결하지 않고 가입을 거부합니다. 계정 생성 후 명단 등록 실패 시 생성 계정을 정리합니다.

교사는 학생의 표시 이름과 번호를 수정할 수 있지만 처음 정한 로그인 이름은 바뀌지 않습니다. 입장 중지는 서버 로그인과 RLS 자료 접근을 차단하고, 입장 재개 후에는 동일한 이름·비밀번호를 사용합니다. 비밀번호 초기화 UI는 포함하지 않습니다. 비밀번호 분실 시 운영자가 Supabase Auth에서 해당 학생 계정의 비밀번호를 재설정해야 합니다.

초기 설정으로 이름별 15회/10분, 접속 IP별 300회/10분 요청 제한을 적용합니다. 원본 IP 대신 서버 비밀 값과 함께 해시한 키만 요청 제한 테이블에 저장합니다. 실제 학급 수·학교 네트워크에 맞춰 운영자가 제한을 조정하세요.

## 비공개 이미지 저장
`writing-submissions` 버킷은 비공개이며, 각 10MB 이하 PNG/JPEG/WebP를 제출당 최대 20장 저장합니다. RLS로 교사는 자신이 만든 학급의 자료만, 학생은 자신의 자료만 접근합니다. 이미지 URL은 5분간 유효합니다. 학생은 확정 제출 이미지를 바꾸거나 삭제할 수 없습니다. 교사는 피드백·확인 시각만 수정합니다.

미완료 업로드는 API로 정리합니다. 탭 종료나 권한 중지로 미제출 파일이 남을 수 있어 운영자의 주기적 정리가 필요합니다. storage.objects 메타데이터를 직접 SQL 삭제하지 마세요. 사진 EXIF는 자동 제거하지 않습니다. 필요한 부분만 촬영하도록 안내하고 실제 학생 자료의 보관 기간을 정하세요.

## Vercel 및 로컬 실행
Vercel은 `vercel.json`의 Other 프레임워크, `npm run build`, `dist` 정적 출력을 사용합니다. 학생 인증 서버는 Supabase Edge Function이며 Vercel 서버 함수가 아닙니다.

Node.js 22 이상에서:
```sh
npm ci
npm run dev
npm run check
npm run test:rls
npm run test:ui
npm run test:auth
```
http://localhost:5173 을 엽니다. 로컬 연결 변수는 실행 전에 설정합니다. `.env` 파일은 자동 로드하지 않습니다.

SQL 테스트는 PGlite 모의 Auth/Storage 환경에서 RLS·서버 전용 RPC·가입·요청 제한·중지/재개를 검증합니다. UI와 Edge Function 테스트는 모의 Auth API를 사용합니다. 실제 Supabase 통합 테스트를 대체하지 않습니다.

## 연습장 안내
문장 반복, 첫 줄 견본, 흐려지는 따라쓰기, 줄 번호, 십자·점선·미자·네모·4선·밑줄·빈 종이, 서체·종이 색·장식·이미지, A4 세로/가로, 펜·지우개·되돌리기를 지원합니다. 인쇄는 A4, 100%, 여백 없음, 머리글/바닥글 끄기를 권장합니다.

서체는 Google Fonts에서 로드합니다. 설정만 로컬 저장되며 펜 입력·삽입 이미지는 새로고침 후 유지되지 않습니다. 설정 변경 시 펜 입력이 지워집니다. 먼저 저장하거나 제출하세요. AI 글씨 교정은 포함하지 않습니다.


학급 연습 문구 기능: 기존 프로젝트는 `supabase/practice.sql`을 name-password.sql 다음에 한 번 적용합니다. 교사는 대시보드에서 연습 문구를 지정하고, 비워 저장하면 자유 연습입니다. 학생은 로그인 후 연습장으로 이동하며 학생 번호를 표시하거나 새 번호를 부여하지 않습니다. 제출물/피드백은 연습장 상단 링크에서 확인합니다.
