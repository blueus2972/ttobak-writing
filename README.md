# 또박또박 · 손글씨 연습장과 학급 제출함

문구, 격자, 서체, 색상과 종이 방향을 선택하고, 마우스·터치·펜으로 쓴 글을 이미지로 저장하거나 교사에게 제출합니다.

## 화면
- `/` 손글씨 연습장: A4 여러 장 생성, 이미지 PNG 저장, 인쇄/PDF, 학생 제출
- `/teacher.html` 교사: 이메일 로그인, 학급 생성, 학생 등록/수정, 입장 코드 재발급·중지, 제출 검색, 이미지 확인, 피드백
- `/student.html` 학생: 학급 코드 + 개인 입장 코드, 사진 제출, 내 제출물·피드백 확인
- `/setup.html` Supabase 연결 안내

## Vercel 배포
GitHub 저장소를 Import하고 배포합니다. `vercel.json`이 Framework Other, Build Command `npm run build`, Output Directory `dist`를 지정합니다. 프런트엔드 정적 배포이며 Vercel 서버 함수나 관리자 비밀 키가 필요하지 않습니다.

Supabase 연결 전에도 연습장과 이미지 저장은 동작합니다. 실제 제출과 교사 로그인을 활성화하려면 다음 설정을 완료하세요.

## Supabase 연결
1. 프로젝트 SQL Editor에서 `supabase/schema.sql`을 **한 번** 실행합니다. 기존 테이블이 없는 프로젝트를 대상으로 작성한 초기 스키마입니다. 이미 적용한 프로젝트에 다시 실행하지 마세요.
2. 교사 허용 이메일을 등록합니다.
   ```sql
   insert into ttobak_private.teacher_allowlist(email)
   values(lower('teacher@example.com')) on conflict do nothing;
   ```
3. Authentication에서 Email/Password와 이메일 인증을 활성화합니다. 교사 화면에서 계정을 만들고 이메일 인증합니다. 허용 목록에 없는 계정은 교사 권한이 없습니다.
4. Anonymous Sign-Ins를 활성화합니다. 학생은 이메일 계정 없이 익명 인증 세션을 만들고 개인 입장 코드로 자신의 명단과 연결됩니다.
5. Site URL 및 Redirect URLs에 실제 Vercel 사이트 주소를 등록합니다.
6. Vercel 환경 변수에 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 등록합니다. 이전 anon 공개 키는 `SUPABASE_ANON_KEY`를 사용할 수 있습니다. 관리자 `service_role` / `sb_secret_` 키는 사용하지 마세요. 빌드 스크립트가 관리자 키를 거부합니다.
7. 최신 커밋으로 재배포하고 테스트 교사·학생으로 제출→교사 피드백→학생 확인 흐름을 검증합니다.

URL과 공개 키만으로는 스키마·교사 허용 목록·인증 설정을 변경할 수 없습니다. 이 설정은 Supabase 대시보드 권한을 가진 운영자가 수행해야 합니다.

## 저장·접근 권한
- 비공개 `writing-submissions` 버킷, 한 파일 10MB 이하, PNG/JPEG/WebP, 한 제출 최대 20장.
- PostgreSQL RLS로 교사는 자신의 학급만, 학생은 자신의 자료만 조회합니다.
- 학생별 무작위 128비트 입장 코드를 발급하며 DB에는 SHA-256 해시만 저장합니다. 원래 코드는 발급 직후 한 번만 표시됩니다. QR이나 학생 링크에 코드를 넣지 않습니다.
- 학생 코드 재발급/중지는 기존 인증 세션의 명단 연결을 지웁니다. 기존 signed image URL은 발급 후 최대 5분 동안 유효할 수 있습니다.
- 제출물 피드백·확인 시각만 교사가 수정할 수 있습니다. 학생은 제출된 이미지와 피드백을 수정하거나 삭제할 수 없습니다.
- 실패한 제출의 업로드 파일은 API로 정리합니다. 코드가 업로드 도중 회수되거나 탭이 닫히면 미제출 파일이 남을 수 있습니다. 운영자가 주기적으로 미제출 이미지를 Storage API로 정리하세요. storage.objects 메타데이터를 SQL로 직접 삭제하지 마세요.
- 사진 파일명은 저장하지 않으며 UUID 경로를 사용합니다. 이미지의 학생 개인정보나 EXIF는 별도 자동 제거하지 않습니다. 필요한 부분만 촬영해 제출하도록 안내하세요.

학생 명단·실제 입장 코드·이미지·관리자 키는 GitHub에 올리지 마세요. 프로덕션에서 프로젝트의 인증 요청 제한 및 보관 기간을 정하고 실제 Supabase 권한 테스트를 수행한 뒤 학생에게 배포하세요.

## 로컬 실행과 확인
Node.js 22 이상에서:
```sh
npm ci
npm run dev
npm run check
npm run test:rls
npm run test:ui
```
http://localhost:5173 을 엽니다. 연결 환경 변수는 실행 전에 설정합니다. `.env` 파일은 자동 로드하지 않습니다.

RLS 테스트는 PGlite Postgres 환경에 모의 Auth/Storage 테이블과 테스트용 암호 함수 대체 구현을 사용합니다. 교사·학생 격리, 이미지 접근, 제출 권한, 피드백, 미제출 파일 정리, 코드 재발급·중지를 검증합니다. 실제 Supabase Auth/Storage 통합 테스트를 대체하지 않습니다.

## 연습장
문장 반복, 첫 줄 견본, 흐려지는 따라쓰기, 줄 번호, 십자·점선·미자·네모·4선·밑줄·빈 종이, 8개 서체 선택, 종이 테마, 테두리, 장식, 내 이미지, A4 세로/가로, 펜·지우개·되돌리기를 지원합니다.

인쇄는 A4, 배율 100%, 여백 없음, 머리글/바닥글 끄기를 권장합니다. 서체는 Google Fonts에서 로드하며 연결이 없으면 기본 서체를 사용합니다. 설정만 브라우저에 저장됩니다. 펜 입력과 삽입 이미지는 새로고침 후 유지되지 않으며 설정 변경 시 펜 입력은 지워집니다. 먼저 이미지로 저장하거나 제출하세요.

참고 사이트의 코드를 복제하지 않고 기능을 참고해 별도로 구현했습니다. AI 글씨 분석은 포함하지 않습니다.
