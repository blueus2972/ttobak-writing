학급 연결 안내

학생은 처음 이름·비밀번호·학급 코드로 가입하고, 다음부터 이름·비밀번호로 로그인합니다. 가입한 학생은 교사 명단에 자동으로 등록됩니다.

  1. Supabase SQL Editor에서 supabase/schema.sql을 한 번 실행합니다. 이미 적용했다면 이 단계는 건너뜁니다.
  2. 이어 supabase/name-password.sql을 한 번 실행합니다. 이름·비밀번호 학생 계정에 필요한 추가 설정입니다.
  3. 교사로 사용할 이메일을 등록합니다.
    insert into ttobak_private.teacher_allowlist(email)
values(lower('교사이메일@example.com')) on conflict do nothing;
  4. Authentication에서 이메일/비밀번호 로그인을 켜고 교사의 이메일 인증은 유지합니다. 학생은 서버 함수가 별도로 가입 처리하므로 학생 이메일은 필요하지 않습니다. Anonymous Sign-Ins도 켜 둡니다. 이름·비밀번호 확인 전 임시 인증 세션을 만들고 성공 후 정식 학생 세션으로 바꿉니다.
  5. Edge Functions에서 student-account라는 함수를 만들고 서버 함수 코드를 배포합니다. Verify JWT 설정은 켜 둡니다. 인증된 임시 세션으로 호출하고 이름·비밀번호 검증과 요청 제한을 함수 안에서 수행합니다.
    supabase functions deploy student-account --project-ref 프로젝트ID
  6. 서버 함수의 WRITING_ALLOWED_ORIGINS 값을 실제 사이트 주소로 설정하면 해당 사이트의 브라우저 요청만 허용됩니다. Supabase가 서버 함수에 제공하는 SUPABASE_SERVICE_ROLE_KEY는 서버 내부에서만 사용합니다. 이 키를 Vercel이나 프런트엔드에 넣지 마세요.
  7. Authentication의 Site URL 및 Redirect URLs에 실제 Vercel 사이트 주소를 등록합니다.
  8. Vercel 환경 변수에 URL과 공개 키를 등록합니다.
    SUPABASE_URL=https://프로젝트ID.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
    기존 anon 공개 키는 SUPABASE_ANON_KEY로 사용할 수 있습니다.
  9. Vercel에서 재배포한 뒤 교사 계정을 만들고 이메일 인증·로그인합니다. 학급을 만들고 학급 코드를 학생에게 안내합니다. 새 기기에서도 학생 이름·비밀번호로 로그인되는지 테스트하세요.

학생 계정 안내

처음에는 ‘처음 시작해요’를 선택해 이름·비밀번호·비밀번호 확인·학급 코드를 입력합니다. 이후 ‘다시 왔어요’에서는 이름과 비밀번호만 받습니다. 같은 이름이 이미 있으면 반이나 번호를 붙여 다른 로그인 이름을 정합니다.

교사는 학생의 표시 이름·번호를 바꾸거나 입장을 중지·재개할 수 있습니다. 로그인 이름은 처음 정한 이름을 유지합니다. 비밀번호 분실 시 운영자가 Supabase Auth에서 재설정해야 합니다. 학생 비밀번호는 교사 화면에 표시되지 않습니다.

비공개 Storage와 RLS로 교사는 자신의 학급, 학생은 자신의 제출물만 접근합니다. 교사가 입장을 중지하면 로그인과 자료 접근이 차단됩니다. 이미 발급한 이미지 링크는 최대 5분간 유효할 수 있습니다.
